### Module 01: Callables & Functional Python
- **Folder**: `01_callables_and_functional_python/`
- **Core Topics**: First-class functions, higher-order functions, `__call__` magic method on classes, closures, decorators with `@functools.wraps`, callable inspection via `inspect.signature` and `inspect.getdoc`, callback hooks (pre-execution, post-execution).
- **Agent Connection**: Every AI tool in an agent runtime is fundamentally a Python callable. The LLM produces a string with tool name and arguments; the runtime resolves this string against a dictionary/registry of callables and invokes it. Decorators wrap tool functions to log execution, enforce rate limits, and sanitize outputs.
- **Key Terms to Document**:
  - `Callable`: Any object responding to `()`, including functions, lambdas, and classes implementing `__call__`.
  - `Higher-Order Function`: A function accepting another function as an argument or returning one (used for tool middleware).
  - `Closure`: An inner function retaining access to variables in its enclosing scope (used for parameterized tools with state).
  - `Decorator`: A syntactic wrapper (`@`) transforming or instrumenting a callable without changing its source code.
  - `Function Introspection`: Programmatic examination of callable signatures and docstrings to generate LLM tool schemas.
- **Required Runnable Python Files**:
  - `callables_demo.py`: Demonstrates functions, lambda, class with `__call__`, and inspecting signatures.
  - `tool_decorator.py`: Demonstrates `@tool` decorator extracting metadata, type signatures, and registering into a global tool map.

### Module 02: Classes, Dunder Methods & OOP Patterns
- **Folder**: `02_classes_dunder_and_oop/`
- **Core Topics**: `__init__`, `__repr__` and `__str__` (for injecting agent and tool state into LLM prompts), `__enter__` / `__exit__` and `__aenter__` / `__aexit__` (managing database connections, temporary directories, and API sessions), `__getitem__` / `__setitem__` (dictionary-like message stores), `__len__`, `__iter__`, Abstract Base Classes (`abc.ABC`, `@abc.abstractmethod`), polymorphism for Model Providers and Memory Backends.
- **Agent Connection**: Agent runtimes use polymorphism to decouple business logic from external providers. An agent depends on an abstract `BaseLLMProvider` which can be swapped between `OpenAIProvider`, `AnthropicProvider`, `OllamaProvider`, or `MockProvider` without touching core orchestration.
- **Key Terms to Document**:
  - `Dunder Method`: Special methods prefixed and suffixed by double underscores controlling Python object behavior.
  - `Context Manager`: An object defining runtime context via `__enter__` and `__exit__` for guaranteed resource cleanup.
  - `Abstract Base Class (ABC)`: A class that cannot be instantiated, prescribing an interface contract for subclasses.
  - `Polymorphism`: The ability of different classes to respond to the same interface method in provider-specific ways.
  - `Composition over Inheritance`: Building agents by assembling modular components (memory, tools, model) rather than deep subclassing.
- **Required Runnable Python Files**:
  - `dunder_patterns.py`: Demonstrates `__repr__` for prompt formatting, `__getitem__` for message logs, and `__enter__`/`__exit__`.
  - `abstract_providers.py`: Demonstrates `BaseLLMProvider` ABC with concrete `MockProvider` and `LocalRuleProvider` classes.

### Module 04: Async/Await, Asyncio Event Loops & Tasks
- **Folder**: `04_async_and_event_loops/`
- **Core Topics**: Coroutines, event loop lifecycle (`asyncio.run`), non-blocking I/O vs CPU blocking, `asyncio.gather` for concurrent operations, `asyncio.create_task` for background workers, task cancellation, timeouts via `asyncio.wait_for`, `asyncio.Semaphore` for concurrency throttling, running blocking synchronous functions via `asyncio.to_thread`.
- **Agent Connection**: AI agents spend virtually all their time waiting on external network I/O (LLM generation, search API calls, database reads). Async allows an agent to execute 5 search queries or tool calls concurrently in 1 second instead of 5 sequential seconds.
- **Key Terms to Document**:
  - `Coroutine`: A function defined with `async def` that can pause execution via `await` yielding control back to the event loop.
  - `Event Loop`: The central scheduler managing and distributing execution across cooperative async tasks.
  - `Task`: A wrapped coroutine scheduled on the event loop that runs concurrently.
  - `asyncio.gather`: Mechanism to run multiple awaitables concurrently and collect their return values.
  - `Semaphore`: A synchronization primitive restricting the maximum number of concurrent tasks (crucial for API rate limits).
- **Required Runnable Python Files**:

  - `concurrent_tools.py`: Demonstrates executing multiple agent tools concurrently with timeout protection and semaphores.

### Module 05: ContextVars & Request/Task-Scoped State
- **Folder**: `05_contextvars_and_state/`
- **Core Topics**: `contextvars.ContextVar`, thread-local vs task-local storage, context inheritance across `asyncio.create_task`, `copy_context()`, token lifecycle (`set` and `reset`), preventing context bleeding across concurrent agent requests.
- **Agent Connection**: In multi-tenant agent runtimes (like FastAPI web services or multi-agent swarms), dozens of agent requests execute concurrently in the same process and event loop. `ContextVar` allows trace IDs, tenant IDs, auth tokens, and cancellation signals to be accessible anywhere deep in the call stack without polluting every function signature.
- **Key Terms to Document**:
  - `ContextVar`: A Python standard library variable that holds values local to the current asynchronous execution context.
  - `Task-Local Storage`: Data isolated to a specific async task hierarchy, preventing cross-talk between concurrent coroutines.
  - `Token`: An object returned by `ContextVar.set()` used to restore the variable to its prior value via `ContextVar.reset()`.
  - `Context Leaking`: A bug where state from one request inadvertently bleeds into another due to unmanaged global state.
- **Required Runnable Python Files**:
  - `contextvars_demo.py`: Basic task-scoped variable propagation across nested async functions.
  - `tenant_isolation.py`: Simulates concurrent multi-tenant agent runs, proving that tenant IDs and trace IDs remain strictly isolated.

  - `State Transition Guard`: A boolean condition that must evaluate to true before a transition to another state is allowed.

### Module 15: Math Bridges for AI Agents
- **Folder**: `15_math_bridges/`
- **Core Topics**:
  1. Linear Algebra & Vector Embeddings: Vectors as semantic coordinates, dot product, Euclidean norm ($L_2$), cosine similarity:
     $$\text{cosine\_similarity}(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}$$
     Vector normalization, top-k retrieval for Retrieval-Augmented Generation (RAG).
  2. Calculus & Loss Gradients: Objective functions, gradient descent intuition ($w \leftarrow w - \eta \nabla L$), step size / learning rate, loss minimization, why LLM outputs are probability distributions.
  3. Probability & Confidence Scores: Logits, softmax function with temperature scaling:
     $$P(w_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$
     Top-p (nucleus) sampling, entropy/confidence evaluation, expected value in decision-making ($E[R] = \sum P(a) R(a)$) for agent plan reflection and tool selection.
- **Agent Connection**: Connects abstract mathematical principles to the exact mechanisms driving agent behavior: embeddings power agent semantic memory and document search; temperature dictates whether tool calling is strictly deterministic or creative; expected value guides decision tree search.
- **Key Terms to Document**:

  - `Cosine Similarity`: Dot product of two normalized vectors measuring angle/semantic closeness between -1 and 1.

## 4. Detailed Specification for the `mini_agent` Project

The `mini_agent` project serves as the unifying capstone for Course 0. It must integrate async execution, SQLite persistence, Pydantic data modeling, ContextVars, tool sandboxing, and error recovery into a standalone runnable architecture without external API key requirements.

### 4.1 Architecture Diagram
```
User / CLI
    │
    ▼
MiniAgent Runtime (ContextVars: trace_id, session_id)
    │
    ├─► Memory Store (SQLite: messages, sessions, audit_log)
    │
    ├─► Tool Registry (Callables, Pydantic schemas, validation, sandboxing)
    │      ├── calculator
    │      ├── local_search
    │      ├── echo
    │      └── run_python
    │
    └─► Reasoning Engine (Deterministic ReAct Engine: Thought -> Action -> Observation -> Answer)
```

### 4.2 Module Components & Files
1. `mini_agent/__init__.py`: Package entry points exporting `MiniAgent`, `ToolRegistry`, `AgentConfig`.
2. `mini_agent/config.py`:
   - `AgentConfig`: Pydantic settings model specifying `agent_name`, `max_steps`, `db_path`, `timeout_seconds`, and `temperature`.
3. `mini_agent/models.py`:
   - `MessageRole` (`system`, `user`, `assistant`, `tool` enum).
   - `ToolCall` (id, tool_name, arguments).
   - `ToolResult` (call_id, success, output, error).
   - `Message` (role, content, tool_calls, tool_results, timestamp).
   - `AgentStep` (thought, action, action_input, observation).
4. `mini_agent/memory.py`:
   - `SQLiteMemory`: SQLite database manager with WAL mode and tables:
     - `sessions` (`session_id`, `created_at`, `metadata`)
     - `messages` (`id`, `session_id`, `role`, `content`, `timestamp`)
     - `tool_audit` (`id`, `session_id`, `trace_id`, `tool_name`, `args`, `result`, `success`, `duration_ms`)
   - Methods: `add_message`, `get_history(session_id, limit)`, `log_tool_call`, `clear_history`.
5. `mini_agent/tools.py`:
   - `ToolRegistry`: Registry storing registered callables.
   - `@tool` decorator automatically extracting docstrings and Pydantic schemas.
   - Built-in tools:
     - `calculator(expression: str) -> float`: Safe mathematical expression evaluation using AST (preventing `eval` exploits).
     - `local_search(query: str, domain: str) -> list[str]`: Simulated semantic knowledge retrieval.
     - `run_python(code: str) -> str`: Safe subprocess execution with timeout and output capture.
     - `get_time() -> str`: System time provider.
6. `mini_agent/engine.py`:
   - `DeterministicReActEngine`: A reasoning engine simulating an LLM ReAct loop without external API keys.
   - Parses goal, generates structured `Thought`, decides next `Action`, parses `Observation` from tool output, and produces `Final Answer`.
   - Supports simulated error correction: if a tool throws an error, engine formulates a corrective retry step.
7. `mini_agent/agent.py`:
   - `MiniAgent`: Core async coordinator.
   - Sets up `ContextVar` for `trace_id` and `request_id`.
   - Iterates through the ReAct loop up to `max_steps`.
   - Persists state into `SQLiteMemory` at each turn.
   - Handles graceful cancellation, timeouts, and unexpected exceptions.
8. `mini_agent/main.py`:
   - Runnable demonstration script running several multi-step tasks (e.g. arithmetic computation, file/knowledge search, python execution).
9. `mini_agent/tests/test_mini_agent.py`:
   - Pytest suite verifying:
     - Tool registration and schema extraction.
     - Parameter validation and error rejection.
     - SQLite memory persistence and history retrieval.
     - ContextVar trace propagation.
     - End-to-end autonomous task resolution.
